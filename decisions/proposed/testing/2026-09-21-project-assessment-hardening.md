# Agent Note: 门禁内容快照与升级边界加固

Status: proposed

## Problem

[项目评估](../../../reports/project-assessment.md)发现，正常路径检查通过不能保证 Git 待提交内容、
既有 hooks 与升级目标边界的正确性；模板升级、任务状态和交付流程也有跨模块契约缺口。

## Proposal

按评估优先级分任务实施。首先明确每个门禁针对的内容快照，再补文件写入与任务生命周期的
后置条件；其次处理模板所有权、教程、CI 与可恢复发布。保留零运行时依赖与当前知识分层。

- 凭据检查区分 index、工作树与提交历史；决策门禁保留 diff 状态并校验目标记录存在。
- task start 检测并安全衔接既有 hooks，明确新建与恢复的状态转换。
- upgrade 写入前检查真实路径边界；可扩展索引保留用户内容，写入具备可核对的变更清单。
- CI 合同区分静态门禁与本地 worktree 纪律；声明的运行时支持范围由相应测试覆盖。
- 发布使用已验证的产物，记录阶段状态并支持同版本恢复；准备前检查 tag、任务和精确远端基线。

本记录是待审方案，不是已实施修复；具体问题证据与执行结果只放评估报告。

## Alternatives considered

**只增加文档警告** — 不采用：不能防止自动化错误放行，也不能保护实际文件写入边界。

**仅提高覆盖率阈值** — 不采用：现有高覆盖模块仍有内容快照及功能组合缺口，必须增加有行为
判别力的反例。

**一次重写 CLI 或引入大型框架** — 不采用：问题集中在跨模块契约，全面重写会扩大回归面，
并不直接改善失败恢复。

## Acceptance criteria

- 合成识别标记留在 index 而工作树安全时，提交门禁失败，输出不包含标记内容。
- 新任务 worktree 中既有拒绝型 hook 继续拒绝提交；无法衔接时创建过程清楚失败。
- upgrade 拒绝目标目录之外的链接写入，拒绝时外部内容不变。
- 仅删除决策、无有效新增或修改记录时不能满足决策要求。
- cookbook new 后运行 upgrade，自定义页面和索引关系均保留。
- DONE key 的 start 被拒绝或走明确 reopen，成功返回后 task check 通过。
- 从空目录执行教程可完成首个任务；CI 与本地模式有明确、可测试的执行合同。
- 两包发布中断可恢复同一版本，实际发布产物与验证产物一致。

## Risks

- hook 继承与跨平台路径行为需要真实集成测试，不能只断言配置字符串。
- 严格路径和内容快照校验可能改变消费方既有行为，需要同步升级说明与错误提示。
- 发布恢复跨 registry 与 Git，没有全局事务；阶段记录应明确不可逆操作。
- 本轮不提前实现上下文检索，不把评估工具加入默认产品测试入口。
