# 共享工具链：一套就够，全员共用

同一台机器上出现多套 JDK / 构建工具 / 语言运行时，每个 AI 会话各装一套，磁盘、PATH 与"到底用哪
个版本"越来越乱。本手册把"选定一套、以后共用"落成可执行步骤；示例是 Java，方法对任何工具链通用。

## 1. 触发场景

- 用户说"系统里四五套 JDK，IDEA 一套、命令行一套，AI 又各装一套"。
- 新会话第一件事是"装个环境"，而不是先看已有的。

## 2. 探测已有的

```sh
/usr/libexec/java_home -V        # macOS：列出全部 JDK
which -a java mvn python3 node   # 命令解析到哪几个
java -version; mvn -v; node -v
```

把输出留痕（报告或任务卡）。探测之前不要安装任何东西。

## 3. 选定唯一供给源

优先选**已经在用、被 IDE 或 CI 引用的那套**，而不是最新版；定下绝对路径、版本与谁在用。

## 4. 让所有会话与工具都用它

- 声明：在项目里新建 `docs/cookbook/toolchain.md` 记下实际路径与版本，或写进项目 README 一节。
- 常驻命令：根 AGENTS.md 加一条"不得新装 <工具>；用 <路径>"，理由指向本文件。
- 环境：项目脚本与 IDE 配置指向同一路径（`JAVA_HOME`、toolchain 配置、`.nvmrc`）。
- 检测：写一条能一眼判定的命令，见下节。

## 5. 验证

```sh
java -version; echo "$JAVA_HOME"   # 或 node -e "console.log(process.execPath)"
```

期望：输出与第 3 步的路径一致。新会话问一遍"用哪套"，回答应指向同一路径。

## 失败与回退

- 确实需要第二套版本：不改 canonical，用项目级 override，并在同一份文档写明谁是例外、为什么、
  什么时候收回。
- 工具装在别的用户或别的盘：只记录路径，不要复制安装目录。

## 验证清单

- 探测命令的完整输出已留痕。
- canonical 路径出现在根 AGENTS.md 的常驻命令里。
- 检测命令输出等于 canonical 路径。
- 例外至多一条，且写了回收条件。
