# 核心理念

## 一句话

把"现在是什么样""为什么这样定""做到哪一步""这次怎么做的"从对话和脑子里搬进仓库，用
Markdown + Git 承载——任何人和任何 AI 编程工具都能接手。

## 要解决的问题：文档为什么会腐化

- 事实写进一个 README 后没人回头改，几周后它就在说假话。
- 决策只剩结论，没人记得当初为什么否决了另一种做法，于是同样的坑反复踩。
- 进度散在聊天、issue 和看板里，仓库里的代码看不出做到哪一步。
- 换一个 AI 编程工具，上下文要重新讲一遍，规则还讲不全。

## 解法：四层知识，每层只回答一个问题

| 目录 | 只回答 | 不归它管 |
| --- | --- | --- |
| [docs/](AGENTS.md) | 现在是什么样（当前事实） | 为什么、过程 |
| [decisions/](../decisions/README.md) | 为什么这样定、放弃了什么 | 变更史 |
| [tasks/](../tasks/README.md) | 做到哪一步（状态） | 任务内容细节 |
| [reports/](../reports/README.md) | 这次怎么做的（过程） | 长期结论 |

分层只有一条硬规则：**每个事实只有一个家**。别处需要它时，只放一条相对链接，绝不复制。

写文档时只写当前状态，不写"之前……现在……"的变更史——变更史属于 commit 与 reports/。

## AGENTS.md：让 AI 自动读到规则

根 [AGENTS.md](../AGENTS.md) 只放每次会话都必须在场的常驻命令，每条 1–3 句并链接它的"家"；
`docs/`、`decisions/`、`tasks/`、`reports/` 各有自己的 AGENTS.md，写该目录专属规则。

AI 编程工具按当前目录自动收到对应规则，不需要你每次重新交代。规则改了，AI 下次就读到新的。

## 门禁：让腐化在提交前失败

```sh
pnpm verify:docs
```

一次覆盖五件事：链接与锚点可解析、决策记录结构与格式合规、任务头字段合规、常驻文档不超
字数预算、工作模式取值合法。零依赖，只跑 Node 内置模块。

门禁是护栏，不是装饰：规则一旦机器可校验，就不依赖"记得去改"。

## 工作模式：先规划还是先动手

真源在 [.psycho-frame.json](../.psycho-frame.json) 的 `workMode`：

- `plan`：`on` 时改动前先给计划并等确认。
- `confirmAmbiguous`：`true` 时需求有歧义必须先问，禁止自行假设。
- `fleet`：`on` 时可独立切分的批量工作优先派发子代理并行，主线程留决策与验收。

```sh
pnpm exec psycho-frame mode
pnpm exec psycho-frame mode set plan=off
```

## 零运行时依赖，换 Agent 零迁移

知识载体只有 Markdown + Git；工具只依赖 Node ≥ 18.20 内置模块，没有数据库、没有 SaaS
看板、没有私有格式。想换框架、换编辑器、换 AI 工具，仓库原样带走。

装好骨架后的第一件事，看 [使用教程](cookbook/tutorial.md)。
