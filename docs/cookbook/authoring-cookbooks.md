# 把重复出现的痛点整理成 cookbook

用户用大白话抱怨"每次都要这样"、"这帮 AI 各自搞一套"、"我希望以后大家共用一套"时，把它整理成
cookbook，下次同类会话不必重新商量。本文件是判定标准与访谈问题；生成骨架用 `psycho-frame
cookbook new`。

## 1. 判定够格

四条同时满足才写：

- 重复出现：不只这一次，或明显会再遇到。
- 跨会话：换个会话、换个人、换个 agent 就会重新踩。
- 可验证：有能判定"做对了"的命令或观察点。
- 有稳定做法：结论不依赖当时的临时上下文。

只发生一次、或结论仍在校验中，先写 issue 或报告，不写 cookbook。

## 2. 五个问题

问用户，不要替他假设：

1. 什么时候会发生？（触发场景）
2. 现在怎么做？（含手工动作的实际步骤）
3. 为什么不行？（痛点与代价）
4. 正确的做法是什么？（期望的稳定形态）
5. 怎么验证做对了？（命令或观察点）

问不出来就先按第 4 条给草案并标注待确认；不要用"应该""大概"填空。

## 3. 落地

```sh
psycho-frame cookbook new <slug> --title "<标题>"
```

命令生成骨架、登记索引、登记字数预算；随后按第 2 步的答案填步骤。重复出现的约束要落到下次会话
一定看得到的位置：根 AGENTS.md 加一条常驻命令指向本文件（细节的唯一家仍是 cookbook）。

范例见 [shared-toolchain.md](shared-toolchain.md)：用户说"系统里四五套 JDK / Maven，AI 每家自己
搞一套，我希望有一套以后大家共用"，落成"选定唯一供给源 + 写进常驻命令 + 一条检测命令"。

## 4. 反模式

| 你写下的内容 | 该去哪 |
| --- | --- |
| 为什么这么定、放弃了什么 | [decisions/](../../decisions/README.md) |
| 事故是怎么发生的 | [postmortem/](../postmortem/README.md) |
| 本次任务做了什么 | [reports/](../../reports/README.md) |
| 一次性环境说明 | 任务卡或 issue |

## 验证清单

- 五问都有答案，没有"应该 / 大概"。
- 步骤含可复制命令与失败处置。
- 索引与预算已登记（`cookbook new` 自动完成），`pnpm verify:docs` 通过。
- 重复出现的约束在根 AGENTS.md 有常驻命令指向本文件。
