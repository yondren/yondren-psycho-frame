# 整理项目文档

索引开始逐条登记历史，或长期任务的批次记录同时出现在多份文档时，把下方提示词交给项目 Agent。

## 可复制提示词

```text
整理当前仓库的文档，遵循项目 AGENTS.md 和文档门禁。目标是缩短常用入口，
同时在仓库里保留原文和证据，供后续 Agent 按需检索。

1. 先看入口和目录。用 rg --files docs decisions tasks reports 看文件分布，再用
   rg -l -F '实际关键词' docs decisions tasks reports 列出命中的文件。在选中的文件用
   rg -n -F '实际关键词' 文件路径 定位小节。也可按任务号或批次号查找。范围过大时
   按主题分批。对照代码、配置、当前决策或任务卡验证事实，无法确认的列为待核实
   并留在原处。

2. 精简入口。索引只列主题、用途、当前权威文档和历史资料所在目录，保留必要的
   规则和导航链接。移除已经能在报告或决策中按需找回的逐条历史入口。下次新增
   记录时，在主题路由有变化时更新索引。项目若已有逐条登记约定，按项目流程
   更新该约定后再应用主题索引。

3. 保留原文。让当前事实、决策理由、任务状态和执行过程各有一个权威出处。
   活跃任务卡保留状态、阻塞、下一步和报告链接，历史批次归报告。
   已被替代且无当前职责的文档，按项目已有归档规则移动；仅移出索引的历史
   报告可以留在原目录。拆出历史段落前，保留原文、标题、证据链接及检索线索，
   并在需要追溯的地方链接到其新位置。文件年龄、长度和任务状态仅用于定位候选。
   保持任务卡和报告的路径约定，遵守既有归档的冻结规则。

4. 验证。移动前按原文件名查找引用，移动后核对入站链接、相对出站链接和锚点。
   检查 git status --short 与 git diff --name-status -M HEAD，确认每份原文仍有去处。
   运行 pnpm verify:docs 或项目等价门禁；有失败时修复本次变更引入的问题。
   从精简后的入口找到一条当前规则，再用任务号、批次号或关键词找回一条历史
   记录。交付时列出精简的入口、原文的去向、待核实项和验证结果。
```

文档分层见 [文档标准](../AGENTS.md)，决策归档格式见 [决策记录](../../decisions/README.md)。
